The handoff nobody has automated

Ask an assistant to help with something you just did in a browser — file the bug, draft the release note, review the flow, write the spec — and you start the same way every time: screenshot it, then type out the steps by hand.

That is the work GuideGen removes, and it does not care who reads the result. Copy for AI puts the steps, the action taken at each one and the page each happened on straight onto your clipboard, as text — ready to paste. The same recording also exports as a document for the people who need one.

It also carries what the page did, not just what you clicked: the requests each step fired and the status that came back. A bug report that says clicking Refund sent POST /api/refunds and got a 500 is one an engineer or a model can start on. That log travels with the handoff and with nothing else — documents, slides and video never include it.

Same chore, different desks: a QA engineer filing a reproduction, a product manager writing an enhancement spec or a UX review, product marketing drafting a release note, HR walking a new joiner through a system for the first time. One recording covers all of them.

What the page actually did

Each step also records the requests it fired and what came back — POST /api/orders → 500 — and for a request that failed, the whole exchange as a curl you can copy: the headers, the body that was sent, the body that came back. That turns "I clicked Save and it didn't work" into a bug report a developer or a model can act on without asking you to do it again. Credential values are masked before anything is stored. Failures surface on the step; the full log is one click away, and it goes in the AI handoff only.

Instructions, written for you

Step text comes from the control you actually clicked — its label and its role — not a generic "click here". Fields, dropdowns, checkboxes and keystrokes each read the way a person would write them.

Screenshots that make sense

Each step is captured at the moment you clicked, with the target lifted out and numbered. Guides crop to the part of the page that matters instead of shrinking the whole window until nobody can read it.

Redaction that actually redacts

Drag a box over anything sensitive and it is pixelated in every export, permanently. Password fields are masked the moment they are captured.

Questions worth asking first

Which AI does the handoff work with?

All of them. It copies plain text to your clipboard — Markdown, with the steps grouped under the page each happened on — so it pastes into Claude, ChatGPT, Gemini, Copilot, an IDE, a Jira ticket or a plain note. There is no integration to configure and no API key to hand over, which also means nothing is sent anywhere until you paste it yourself.

Does the AI handoff include the screenshots?

No, and that's deliberate. Forty screenshots as embedded data would be several megabytes of text that no chat window will accept, and a model told to expect images that never arrived will describe them anyway. The handoff is the written record — the steps, the actions and the URLs. When the pictures matter, attach them from the Markdown or PDF export, or send the shareable link.

Does the API log clutter up the guide?

No, and that was the design problem. A single-page app fires requests on nearly every click, so printing them all under every step would bury the guide. Instead a step where everything succeeded shows one muted line — 5 requests — that doesn't expand. A step where something failed shows the failures straight away, because that's the case you opened the guide for. Everything, in full and untrimmed, lives in one API log panel you open from the toolbar, with a "failed only" filter and a copy button.

Which exports include the API log?

Only the AI handoff. HTML, Markdown, PDF, PowerPoint, narrated video and published shareable links all leave it out — a guide someone is following doesn't want GET /api/session → 200, and a video certainly doesn't. If you want just the log and not the guide around it, there's a copy button inside the log panel.

The cURL has my headers in it. Does that mean my tokens?

No. A header whose name looks like a credential — authorization, cookie, x-api-key and the like — keeps its name and loses its value, replaced with a marker before anything is stored. There is no setting that changes that. The same happens to query-string values and to obvious secrets in a submitted body, so a password field never lands in a log. Your browser cookies aren't readable this way at all. The practical consequence: the cURL documents the call, it does not replay it — paste your own token in if you want to re-run it.

The full exchange is itself a separate opt-in that is off by default, and even switched on it only ever keeps a request that failed, trimmed. The reason it's off: everything else GuideGen records you can see and black out, but a request and response body are data you never looked at. Failures are the narrow case where that content is usually a short error rather than someone's personal data. Any step's log can also be deleted on its own from the editor.

Is GuideGen watching everything I do?

No. It records while you have a recording running, and — separately — on any single site you have switched catch-up capture on for. Nothing else. Catch-up is off everywhere until you turn it on for a specific site, one site at a time, and while it is on there is a dot in the corner of the page saying so. What it holds stays on your device, expires after seven days, and is never uploaded; you can also discard it yourself at any point from your dashboard.

How can it capture the last two minutes if I never pressed record?

Because on a site you've armed it has been capturing all along and discarding as it goes, keeping only a rolling window. There is no clever trick and no way around it — screenshots of the past do not exist, so something has to have been running. That is exactly why this is per-site and off by default rather than always on everywhere, and why the page shows a dot while it is happening.

Can it automate the workflow, not just describe it?

No. GuideGen records what a control was called and where it was on screen, not a selector that would survive the page changing — so the handoff is for explaining and reasoning about a flow, not replaying it. If you want a script, a browser automation recorder is the right tool; this one is for when a person or a model needs to understand what happened.

Does it work outside the browser?

No. GuideGen documents web applications — anything you can open in a Chromium browser. It cannot capture native desktop software.

Can I share a guide as a link?

Yes. Press Publish on a guide and you get a link anyone can open. Only the guide you published is uploaded, and its annotations and redactions are burned into the images before they leave your machine, so no unredacted original is ever sent. You can update it in place — the link doesn't change — or unpublish it, which kills the link and deletes the images. If you'd rather not publish at all, the self-contained HTML export is a single file you can drop into Google Drive, Notion, SharePoint or an email.

Why do I need an account?

Two reasons. The editor lives on this site rather than inside the extension, so there is one editor to keep good instead of two, and it needs to know whose guides to show you. And publishing has to be tied to an identity so that you — and only you — can update or delete a shared guide later. Signing in does not upload anything: guides you have not published stay in your browser's own storage on that machine.

Can I edit a guide on another computer?

Published guides, yes — sign in anywhere and they're there. Unpublished ones, no: they live in the extension's storage on the machine that recorded them, which is the direct consequence of not uploading anything until you ask. That is the design working, not a limitation we forgot about.

What languages does it handle?

Step descriptions are generated in English at the moment. It will happily record an interface in any language, but the sentences it writes around it are English.

Why does it ask for access to all websites?

Because it cannot know in advance which application you'll want to document — it might be any internal dashboard. The recorder does nothing until you press start — or, on a site you've switched catch-up capture on for, until you work on that site — and it reads only the label and position of the element you click, plus the request summary described above. It also asks to observe network requests, which is what the API log is; it cannot block, redirect or alter one, and credential values are masked before anything is stored.

Is it really free?

Yes, and with no card required. Paid plans may appear later for team features; if that happens, people already using it get notice and a choice rather than a surprise bill.

How big is the install?

Around 68 MB, which is unusual for an extension. Almost all of it is the neural voice model that lets narration run offline instead of sending your text to a server.
